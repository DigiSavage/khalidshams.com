# khalidshams.com, working notes for Claude Code

This is Khalid Shams's personal site: a static site generated by `build.py`, deployed to S3 + CloudFront by GitHub Actions on every push to `main`, with a Tue/Thu LinkedIn publisher. The mentality: khalidshams.com is meant to become the go-to reference for cloud and AI architecture at principal level. Every change should make it better, not just bigger.

## The one rule that matters most

**No em dashes, en dashes, or " -- " anywhere public.** Not in content, templates, titles, alt text, JSON, or commit messages that end up on the site. They read as AI-written. Use a period, a comma, a colon, or a middle dot (`·`) in titles. Before every commit run:

```bash
grep -rn "—\|–\| -- " templates content static build.py && echo "FIX THESE" || echo "clean"
```

## Voice

Everything on the site is Khalid speaking in the first person, as a practitioner, not a vendor. Plain words, specific examples, mistakes owned ("I set the cost alarm too high", "I nearly resized before I understood"). Pull quotes use `<blockquote class="pq"><p>…</p><footer>Khalid Shams</footer></blockquote>`. Do not invent numbers, clients, or outcomes: every figure and story on the site traces to something Khalid actually did (see `content/posts/` and the case studies in `templates/home.html`). Client names and phone numbers stay off the site. Microsoft is referenced as past experience in site copy; LinkedIn is handled separately and is not this repo's concern.

The four dollar figures on the home page ($7.6M, $5.1M, $4.5M, $532K) come from one role at Microsoft. They must stay inside the "Numbers, in context" block under Selected work with that caveat, never at the top of the page.

## Build, preview, test

```bash
pip install -r requirements.txt            # markdown; cards need Pillow, the publisher needs requests
python build.py                            # -> dist/ ; prints post counts and "search index: N entries"
BUILD_DATE=2027-01-05 python build.py      # preview a future date (posts are date-gated, America/Phoenix)
python -m http.server -d dist 8767
```

Playwright is the visual check (`pip install playwright && playwright install chromium`). Screenshot at 1380 and 390 wide, check `document.documentElement.scrollWidth` equals the viewport (no horizontal overflow), and check `pageerror` is empty. Test search by pressing Cmd/Ctrl+K, typing, pressing Enter, and confirming `mark.ks-hl` elements exist on the destination page.

## Deploy

Push to `main`. `deploy.yml` builds, syncs `dist/` to S3 (no `--delete`), and invalidates CloudFront. Live in about two minutes. Verify with `curl -s https://khalidshams.com/<path> | grep <something new>`. `/dir/` URLs resolve through a CloudFront Function; a 403 from S3 is served as `/404.html`.

Never commit secrets. AWS keys and LinkedIn tokens are GitHub Actions secrets that Khalid manages. Do not touch `.github/workflows/linkedin-token.yml`.

## How to add things

**A post:** `content/posts/YYYY-MM-DD-slug.md` with frontmatter, `status: approved`, a card spec in `tools/cards.py`, then `python tools/make_cards.py`. Tue/Thu dates only; the queue currently runs to 2027-04-29 and needs extending before then. Never set `published` or `linkedin_url` by hand.

**A playbook:** `content/playbooks/07-slug.md` with the same seven `##` sections as the others: What this covers · The questions I ask first (8 numbered, bold lead) · The Azure build, in order (8 numbered steps) · Why each step matters · Real use cases · How it fails · What I leave behind. Then add it to the Playbooks submenu and drawer group in `templates/masthead.html`.

**An idea on the AI map:** append to `content/learn/graph.json` `ideas` (pick a cluster: Foundations, Learning, Language, Agents, Operate, Decide; x,y inside the 1800x800 viewBox; three depths; a `link` into the site), add edges, optionally add to a circuit. Rebuild; the search index picks it up automatically. Deep link is `/learn/?idea=<id>#map`.

**A SHAMS move's detail:** the five panels are generated in `templates/method.html` (the `MOVES`-style markup under `.shams-panels`). Each has: in my words, four questions, estate layers, map ideas, gates, playbooks, "where I got this wrong once".

**A tool:** write `templates/tools/<slug>.html` (copy the shape of `availability.html`: hero with crumbs, the instrument with editor + `.tl-out` results panel, a live `pre.record` note with copy/link/reset, from-the-work lessons, an FAQ on the maths, related links). Add an entry to `TOOLS` in `build.py` (sitemap and search index pick it up), remove it from the bench list in `tools_index.html`, and add it to the Tools submenu and drawer group in `templates/masthead.html`. Rules: example figures are labelled as examples, never presented as vendor prices or SLAs; nothing leaves the browser; share state only through `?s=` in the URL and validate it on load; never round a result in the reader's favour.

**A new section or page:** add a template, render it in `build.py`, add it to the sitemap list, to `build_search_index` pages, and to `templates/masthead.html` (desktop submenu + drawer group). Give every `h2`/`h3` a nearby `id` so search can deep-link and highlight.

Rules: every scene object and step reference must exist in the registry (the build checks). `source-checked` concepts need sources. Colour meaning: cobalt is focus, gold is cost, coral is denial or error, and each also has a non-colour cue (mark, dash pattern, label). No runtime model calls, no framework. Never commit the reference drawings collection.

After registry changes run `python tools/atlas_coverage.py` to regenerate docs/atlas/CONTENT_COVERAGE.md.

Tests: `node --test tests/atlas/*.test.mjs` (engine), `python -m unittest tests/atlas/test_registry.py` (registry), then serve dist on 8767 and run `python tests/atlas/ui_check.py http://localhost:8767 <screenshot dir>` (layout matrix, light and dark, regressions).

## Site search

`build.py` emits `dist/search.json` (one entry per heading section, map idea, and post). `static/search.js` loads it on first open, scores with word-start matching plus a synonym table (`SYN`), groups by page, and on navigation stores the query in `sessionStorage` so the destination page highlights matches with a prev/next/clear pill. Add synonyms to `SYN` when a term has a common alias. Keep it dependency-free.

## Keeping the local copy in sync with GitHub

GitHub is the source of truth and it changes without you: the Tue/Thu publisher workflow commits to `main` (it flips a post to `status: published` and writes `linkedin_url`). So the local clone drifts if it is not pulled. Rules:

1. **Start of every session and before every commit:** `git pull --rebase origin main`. If the rebase reports a conflict in `content/posts/*.md`, keep the GitHub version of `status` and `linkedin_url` (the publisher is right), keep the local version of everything else.
2. **Push immediately after every commit.** Never leave commits sitting locally; `git push origin main` is part of "commit".
3. **Never leave uncommitted work at the end of a session.** Commit and push, or `git stash` with a note, and say which.
4. **Never force-push, never rewrite history on `main`, never delete the remote branch.**
5. Before saying "done", run `git status` (clean) and `git fetch && git status -sb` (must say "up to date" with `origin/main`, not ahead or behind) and report both.

If Khalid wants the folder to stay current even when no session is running, a `launchd` job on the Mac that runs `cd ~/Documents/khalidshams.com && git pull --rebase --autostash origin main` every 30 minutes is enough; the repo has no local-only state, so a pull can never lose anything that was pushed.

The stack

Seven layers. Every AI word you've heard lives in exactly one of them.

Most confusion about AI comes from mixing layers: arguing about the model when the problem is the data, or buying an agent framework when what's missing is a guardrail. Read bottom to top. Each layer only works if the one under it is in place, and that order is also the order I build in.

Four kinds

A model, a chatbot, a workflow, an agent. They are not the same thing.

People say "AI" for all four. The difference is who decides the next step and who takes the action. That difference is also where the risk lives, which is why I ask it first in every engagement.

How an agent thinks

The agentic loop: four stations, one exit.

Strip away the frameworks and every agent is this loop. Your code sends the model the conversation so far. The model replies and says why it stopped: either it wants a tool run, or it is finished. If it wants a tool, your code runs it, appends the result, and goes round again. The only honest exit is the model's own stop reason.

More than one agent

Hub and spoke: one coordinator, specialists with their own tools and their own context.

When the job is too broad for one agent, don't give one agent more tools. Give a coordinator the goal, let it split the work among specialists that each hold a narrow set of tools, and have it assemble the results. Each specialist works in its own isolated context: it cannot see the others' work, which is exactly what keeps it focused and cheap.

The enforcement question

A prompt is a request. A hook is a rule.

The most important distinction in agent design is also the simplest. Anything you write in a prompt is followed most of the time. Anything you put in code around the model is enforced every time. The question for each rule is which of those it needs to be.

Prompt-based

Probabilistic

"Always verify the customer before processing a refund."

Lives in the system prompt. The model reads it, weighs it against everything else in the context, and usually complies. Usually. Under pressure from a long conversation, a persuasive user, or an ambiguous case, it can be argued out of it, and you will not know until the refund has gone.

Hook-based

Deterministic

before tool_call "process_refund":
    if not verified(customer):
        block("verify first")

Lives in code that runs before or after every tool call. The model can want the refund as much as it likes; the hook checks the record and blocks the call. Zero exceptions, every time, with a log entry that says so.

Good for
MoneyComplianceSecurityData accessAnything irreversible

When money is on the line, use hooks, not prompts.

Questions people ask me

The questions that come up in every first conversation.

Short answers, in order of how often I hear them. Each one links back to the idea on the map if you want to go deeper.

Is ChatGPT an agent?

Out of the box it is an assistant: a model with a conversation and standing instructions. It becomes agent-like when it is given tools (browsing, code, files) and allowed to decide when to use them. The product you are using may be either, depending on what is switched on. The test is: does it choose its own next step and act on it? The four kinds.

What is the difference between an LLM and AI?

AI is the whole field. A large language model is one kind of AI: a program that writes by predicting the next word, very well. Spam filters, route planners, and image recognisers are AI too, and most of them are not language models.

Why does it make things up?

Because it is built to produce the most likely next words, not to check them. When it lacks the fact, the most likely words still come out fluently. This is called hallucination. The fix is retrieval (letting it look the fact up in documents you trust), citations, and an evaluation that measures how often it happens.

Why doesn't it remember what I told it last week?

Because a model has no memory of its own. It sees only what is in front of it for this request, called the context window. Products that "remember" are storing notes outside the model and placing them back into the context each time. That is memory as a feature of the system, not of the model.

What is a token, and why do I keep seeing the word?

The small chunks of text a model reads and writes, often parts of words. Everything about a model is counted in tokens: the price, the speed, and how much it can hold at once.

What is a system prompt?

The standing instructions a model is given before the conversation starts: who it is, what it may do, how to answer. It is strong guidance, not enforcement. Anything that must never happen needs a rule in code, not a sentence in the prompt. The enforcement question.

What is RAG?

Retrieval-augmented generation: before the model answers, the system searches your documents for the relevant passages and places them in front of it. An open-book exam instead of answering from memory. It is how you get an assistant to answer from your handbook rather than from the internet in general.

Should we fine-tune a model on our data?

Usually not first. Fine-tuning changes how a model behaves and sounds; it is unreliable at adding facts, and it has to be redone when the facts change. For facts, use retrieval. Fine-tune when you need a consistent style or format, or a small model to do one narrow job cheaply.

What is MCP?

Model Context Protocol, an open standard for connecting tools and data sources to AI models. Think of it as one connector shape: a tool built once as an MCP server works with any model or agent that speaks the protocol. It sits in the tools layer, between the agent and your systems. It standardises how the connection is made, not who is allowed to use it; permissions are still yours to enforce. The stack.

What is the difference between function calling and MCP?

Function calling is how a model asks for a tool to be run: it emits a structured request that matches a schema you declared. MCP is how tools are packaged and discovered so that any model can find and call them. Function calling is the verb; MCP is the plug.

What does "multi-agent" mean, and do we need it?

Several agents with different jobs, usually one coordinating the rest. You need it when one agent would have to hold too many tools or too much context to stay reliable. Most teams don't need it on day one. Hub and spoke.

How do I know if an AI system is safe to let act on its own?

It can tell you what decision it makes and who owns it. It runs as the user, with the user's permissions. Every action is typed, validated, and reversible where it matters. There is a test set that runs on every change, a trace that explains each run, a cost ceiling, and an off switch someone has tested. If any of those is missing, keep a person in the loop. That list is the eight gates, and you can run the check on your own system.
